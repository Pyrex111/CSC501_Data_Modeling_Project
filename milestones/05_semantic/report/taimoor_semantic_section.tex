Embedded Oxigraph stores twelve entity types as 356 fully synthetic instance
triples and loads the ontology into a separate named graph~\cite{pyoxigraph}.
Resource IRIs are local record handles formed from the table name and record ID; business
uniqueness is validated separately. Relationships become IRI edges, scalars typed
literals, and unknown optional values are omitted. Holding and allocation dates,
classification context and captured-source provenance stay distinct, and loading
enables no OWL reasoner.

Six SPARQL SELECT queries reproduce the accepted SQL analyses. Complete result
multisets match, including duplicate multiplicity and unbound optional values;
row counts are 8, 2, 5, 5, 5 and 17, with numeric values compared to ten decimal
places. Q5 lists historical portfolio/disclosure candidates, not a validated
exposure total.

Table~\ref{tab:queries} retains distinctions that an aggregate could hide.
Q1 and Q2 preserve \texttt{contextKey}: identical category labels need not
have equivalent meanings. Q4 uses \texttt{OPTIONAL} to retain disclosures with
unknown publication times. Q5 keeps holding and allocation dates separate;
selecting contemporaneous disclosures and reconciling contexts remain necessary
before deriving portfolio exposure. Q6 traces all seventeen entries through their
snapshots to retained captures. Every query follows stored edges, without
requiring inferred inverses or a reasoner.

All five seeded snapshots are Complete. Grouping by snapshot prevents mixing
disclosure dates, dimensions or blocks, and class filtering keeps
\texttt{weightFraction} out of portfolio holdings. The SELECT reports totals; write
validation applies the prototype $0.005$ tolerance separately, without forcing
Partial or Unknown disclosures to total one.

Graph-backed CRUD stages each change on a candidate, runs the M4 parity checks and
the native validator with capture-file checks, then publishes one atomic SPARQL
delta~\cite{sparqlUpdate}. Writers share one process lock; rejected
operations leave all live quads unchanged. Quickstart builds or reuses the store
and can start Flask on the same instance. Verification passed 189 tests, with
native-only rejection tests bypassing the SQL bridge inside those tests. The six comparisons and the displayed query ran on the same fresh seed, with
AI-executed checks recorded separately from student evaluation.

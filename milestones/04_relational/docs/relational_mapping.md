# ER-to-relational mapping and column dictionary

Owner: Taimoor Shahzad. Prepared 2 November 2026 from the revised two-tab Draw.io model committed on 30 October 2026. The conceptual model remains the source for entity/attribute meanings; `src/dal/sql/schema.sql` is the executable schema contract.

## Mapping decisions

The twelve entity sets map to twelve relations. The thirteen relationship sets are all represented by foreign keys on their many sides. Holding and AllocationEntry already represent the Portfolio-ETF and Snapshot-Category associations; no duplicate junction relations or relationship attributes are introduced. No multivalued attributes, ISA hierarchies or one-to-one relationships are present in this ERD.

Each relation has an autogenerated INTEGER primary key named Id. Internal IDs do not replace business identification rules. Mandatory business/scoped keys are preserved by NOT NULL and UNIQUE; nullable version-dependent and identifier-dependent uniqueness uses explicit partial indexes. Names, email addresses and fund names are not assumed unique.

Scope remains one bank, individual customers, one sampled provider and one ETF fund/share class per ETF record, and one primary source capture per allocation snapshot. New format/context/tolerance details below are implementation choices, not additional course requirements.

## Relationship mapping and cardinality

| Conceptual relationship | Relational mapping | Participation |
| --- | --- | --- |
| Customer Owns Portfolio | `Portfolio.CustomerId -> Customer.Id` | Portfolio has exactly one owner; Customer has 0..* portfolios. |
| Portfolio Has Holding | `Holding.PortfolioId -> Portfolio.Id` | Holding belongs to exactly one portfolio; Portfolio has 0..* holdings. |
| Holding Refers to ETF | `Holding.ETFId -> ETF.Id` | Holding refers to exactly one ETF; ETF has 0..* holdings. |
| ETFIdentifier Identifies ETF | `ETFIdentifier.ETFId -> ETF.Id` | Identifier belongs to one ETF; ETF has 1..* identifiers (pre-commit minimum). |
| ETFProvider Offers ETF | `ETF.ETFProviderId -> ETFProvider.Id` | ETF has one sampled provider; Provider offers 0..* ETFs. |
| AllocationSnapshot Describes ETF | `AllocationSnapshot.ETFId -> ETF.Id` | Snapshot describes one ETF; ETF has 0..* snapshots. |
| ETFProvider Publishes SourceDocument | `SourceDocument.ETFProviderId -> ETFProvider.Id` | Source has one publisher; Provider publishes 0..* source captures. |
| AllocationDimension Dimension of AllocationSnapshot | `AllocationSnapshot.AllocationDimensionId -> AllocationDimension.Id` | Snapshot has one dimension; Dimension has 0..* snapshots. |
| SourceDocument Supports AllocationSnapshot | `AllocationSnapshot.SourceDocumentId -> SourceDocument.Id` | Snapshot has one primary source; Source supports 0..* snapshots. |
| AllocationDimension Categorizes AllocationCategory | `AllocationCategory.AllocationDimensionId -> AllocationDimension.Id` | Category has one dimension; Dimension has 0..* categories. |
| AllocationSnapshot Contains AllocationEntry | `AllocationEntry.AllocationSnapshotId -> AllocationSnapshot.Id` | Entry belongs to one snapshot; Snapshot has 1..* entries (pre-commit minimum). |
| ClassificationScheme Defines AllocationCategory | `AllocationCategory.ClassificationSchemeId -> ClassificationScheme.Id` | Category has 0..1 defining scheme; Scheme defines 0..* categories. |
| AllocationCategory Used by AllocationEntry | `AllocationEntry.AllocationCategoryId -> AllocationCategory.Id` | Entry uses one category; Category is used by 0..* entries. |

Every FK points to the target Id and uses ON UPDATE RESTRICT / ON DELETE RESTRICT. Its name follows `FK_SourceTable_ForeignKeyColumn_2_TargetTable_TargetKeyColumn`. All FK values are required except AllocationCategory.ClassificationSchemeId. A FK alone cannot enforce the parent's 1..* minimum; the transaction validator enforces the two stated parent minimums before commit.

## Common domains

- SQLite STRICT types are INTEGER for keys/references, REAL for fractions, and TEXT for all remaining recorded values. This needs SQLite 3.37.0+.
- Required text is nonempty; identity strings reject surrounding ASCII spaces. Optional text is NULL when unknown, not an empty string. Text uniqueness is case-sensitive. Identifiers/exchange contexts are uppercase.
- Date TEXT values are valid calendar dates in YYYY-MM-DD form. Timestamp TEXT values are fixed UTC YYYY-MM-DDTHH:MM:SS.ffffffZ. Conversion and unknown-publication-time handling are described in the integration contract.
- Country/currency checks enforce two/three uppercase letters, not external registry membership. ISIN checks enforce format, not checksum/registry validity. Dataset evidence must support claimed real values.
- Fractions are in [0,1]. Complete disclosure totals must be within the configurable default 0.005 of 1, inclusive. Partial/Unknown disclosures and sampled holding totals are not forced to 1.

## Relation dictionary

`No (generated)` means that the persisted Id is never NULL but the application should omit it to let SQLite generate it. Asterisks in the ERD correspond exactly to optional descriptive columns here; nullable ClassificationSchemeId arises from the optional relationship.

### Customer

CustomerNumber is mandatory and unique. GivenName/FamilyName describe an individual; Email may be NULL and is not unique.

| Column | SQL type | Nullable | Meaning / key role |
| --- | --- | --- | --- |
| Id | INTEGER | No (generated) | Autogenerated internal identifier; PRIMARY KEY. |
| CustomerNumber | TEXT | No | Existing customer reference within the single-bank prototype. |
| GivenName | TEXT | No | Individual customer given name; descriptive, not unique. |
| FamilyName | TEXT | No | Individual customer family name; descriptive, not unique. |
| Email | TEXT | Yes | Optional contact email; not assumed unique. |

### Portfolio

(CustomerId, PortfolioReference) is mandatory and unique. One customer owns each portfolio; a customer may own zero or more portfolios.

| Column | SQL type | Nullable | Meaning / key role |
| --- | --- | --- | --- |
| Id | INTEGER | No (generated) | Autogenerated internal identifier; PRIMARY KEY. |
| CustomerId | INTEGER | No | Sole owning customer (Owns relationship). FK to `Customer.Id`. |
| PortfolioReference | TEXT | No | Business portfolio reference, scoped to its owning customer. |
| PortfolioName | TEXT | No | Human-readable portfolio description; not unique. |
| BaseCurrency | TEXT | No | Reporting currency; three uppercase letters. |

### Holding

(PortfolioId, ETFId, HoldingAsOfDate) is mandatory and unique. One aggregate ETF position is recorded per portfolio/date. Weights lie in [0,1]; sampled portfolio totals need not equal 1.

| Column | SQL type | Nullable | Meaning / key role |
| --- | --- | --- | --- |
| Id | INTEGER | No (generated) | Autogenerated internal identifier; PRIMARY KEY. |
| PortfolioId | INTEGER | No | Portfolio containing this position (Has). FK to `Portfolio.Id`. |
| ETFId | INTEGER | No | ETF represented by the position (Refers to). FK to `ETF.Id`. |
| WeightFraction | REAL | No | Portfolio weight as a fraction in [0,1]; 0.30 means 30%. |
| HoldingAsOfDate | TEXT | No | Date of this position, YYYY-MM-DD; independent of disclosure date. |

### ETFProvider

(RegistrationJurisdiction, RegistrationNumber) is mandatory and unique. This models a registered legal company, not a person or a brand label alone.

| Column | SQL type | Nullable | Meaning / key role |
| --- | --- | --- | --- |
| Id | INTEGER | No (generated) | Autogenerated internal identifier; PRIMARY KEY. |
| LegalName | TEXT | No | Registered company legal name; not unique. |
| RegistrationNumber | TEXT | No | Company registration identifier issued by the named registry. |
| RegistrationJurisdiction | TEXT | No | Issuing registry/jurisdiction scoping RegistrationNumber. |
| WebsiteUrl | TEXT | Yes | Optional company website; existence/content not verified by SQL. |

### ETF

FundName is not a candidate key. Business identity is resolved through related identifiers. Each ETF has one sampled provider and, before commit, at least one identifier. InceptionDate is optional.

| Column | SQL type | Nullable | Meaning / key role |
| --- | --- | --- | --- |
| Id | INTEGER | No (generated) | Autogenerated internal identifier; PRIMARY KEY. |
| ETFProviderId | INTEGER | No | One sampled offering provider (Offers). FK to `ETFProvider.Id`. |
| FundName | TEXT | No | Descriptive fund/share-class name; not assumed unique. |
| DomicileCountryCode | TEXT | No | Two uppercase letters identifying the recorded domicile. |
| BaseCurrency | TEXT | No | Fund/share-class base currency, three uppercase letters. |
| InceptionDate | TEXT | Yes | Optional inception date, YYYY-MM-DD. |

### ETFIdentifier

ISIN: UNIQUE(IdentifierScheme, IdentifierValue) using a partial index; ExchangeContext must be NULL. Ticker: UNIQUE(IdentifierScheme, IdentifierValue, ExchangeContext), with a required exchange. A nullable three-column unique constraint alone would not protect duplicate ISINs. Format is checked; checksum/registry truth is not.

| Column | SQL type | Nullable | Meaning / key role |
| --- | --- | --- | --- |
| Id | INTEGER | No (generated) | Autogenerated internal identifier; PRIMARY KEY. |
| ETFId | INTEGER | No | Identified ETF (Identifies); each ETF needs at least one identifier. FK to `ETF.Id`. |
| IdentifierScheme | TEXT | No | ISIN or Ticker, exactly. |
| IdentifierValue | TEXT | No | Uppercase nonempty identifier; ISIN additionally has 12-character format. |
| ExchangeContext | TEXT | Yes | Required uppercase exchange context for Ticker; NULL for ISIN. |

### SourceDocument

(Url, RetrievedAt) is mandatory and unique. Retrieval/publication timestamps use YYYY-MM-DDTHH:MM:SS.ffffffZ. A changing URL alone is not a capture identifier. File resolution is checked by the transaction validator when capture_root is provided.

| Column | SQL type | Nullable | Meaning / key role |
| --- | --- | --- | --- |
| Id | INTEGER | No (generated) | Autogenerated internal identifier; PRIMARY KEY. |
| ETFProviderId | INTEGER | No | Recorded publishing provider (Publishes). FK to `ETFProvider.Id`. |
| Url | TEXT | No | URL from which the captured evidence was obtained. |
| RetrievedAt | TEXT | No | Capture timestamp in canonical UTC with six fractional digits. |
| PublishedAt | TEXT | Yes | Optional known publication timestamp in the same UTC representation. |
| CapturedFileRef | TEXT | No | Project-relative path to a retained source capture. |
| DocumentTitle | TEXT | Yes | Optional title making the captured evidence recognizable. |

### AllocationDimension

DimensionName is mandatory, unique and restricted to Sector or Geography.

| Column | SQL type | Nullable | Meaning / key role |
| --- | --- | --- | --- |
| Id | INTEGER | No (generated) | Autogenerated internal identifier; PRIMARY KEY. |
| DimensionName | TEXT | No | Sector or Geography, exactly; values are not part of the column name. |

### ClassificationScheme

A partial unique index protects (SchemeAuthority, SchemeName, Version) only when Version is known. This is conditional business uniqueness, not a candidate key covering unknown-version rows. Unknown versions remain NULL, may have separate records, and must not imply shared category meaning.

| Column | SQL type | Nullable | Meaning / key role |
| --- | --- | --- | --- |
| Id | INTEGER | No (generated) | Autogenerated internal identifier; PRIMARY KEY. |
| SchemeAuthority | TEXT | No | Recorded authority responsible for the classification scheme. |
| SchemeName | TEXT | No | Name of the classification system. |
| Version | TEXT | Yes | Known edition/version label, or NULL when unresolved. |
| DefinitionUrl | TEXT | Yes | Optional reference supporting the scheme definition. |

### AllocationCategory

(AllocationDimensionId, ContextKey, Label) is mandatory and unique, under the documented assumption of one label per context/dimension. Its optional scheme FK implements the ER 0..1 scheme participation. Context helpers and pre-commit validation protect the meaning of used categories; labels/codes alone never prove equivalence.

| Column | SQL type | Nullable | Meaning / key role |
| --- | --- | --- | --- |
| Id | INTEGER | No (generated) | Autogenerated internal identifier; PRIMARY KEY. |
| AllocationDimensionId | INTEGER | No | Category dimension (Categorizes). FK to `AllocationDimension.Id`. |
| ClassificationSchemeId | INTEGER | Yes | Optional defining scheme (Defines); NULL when unknown. FK to `ClassificationScheme.Id`. |
| Label | TEXT | No | Category label, unique only within dimension and ContextKey. |
| Code | TEXT | Yes | Optional published category code; not globally unique. |
| ContextKey | TEXT | No | Deterministic classification-edition or disclosure-local scope token. |

### AllocationSnapshot

(ETFId, AllocationDimensionId, AllocationAsOfDate, SourceDocumentId, SourceLocator) is mandatory and unique. A saved snapshot must contain an entry. SourceLocator distinguishes dated blocks and allocation bases; CoverageStatus controls whether totals must approximate 1.

| Column | SQL type | Nullable | Meaning / key role |
| --- | --- | --- | --- |
| Id | INTEGER | No (generated) | Autogenerated internal identifier; PRIMARY KEY. |
| ETFId | INTEGER | No | ETF described by this disclosure (Describes). FK to `ETF.Id`. |
| AllocationDimensionId | INTEGER | No | One reported allocation dimension (Dimension of). FK to `AllocationDimension.Id`. |
| SourceDocumentId | INTEGER | No | One primary captured source (Supports). FK to `SourceDocument.Id`. |
| AllocationAsOfDate | TEXT | No | Provider observation date, YYYY-MM-DD; distinct from capture/holding dates. |
| BasisNote | TEXT | No | Recorded allocation basis and relevant caveats; nonempty. |
| CoverageStatus | TEXT | No | Complete, Partial or Unknown, exactly. |
| SourceLocator | TEXT | No | One dated allocation block/page/table/row inside the captured source. |

### AllocationEntry

(AllocationSnapshotId, AllocationCategoryId) is mandatory and unique. WeightFraction is in [0,1]. Four SQL triggers preserve matching dimensions during entry writes and later parent edits. Complete totals and nonempty snapshots are validated before commit.

| Column | SQL type | Nullable | Meaning / key role |
| --- | --- | --- | --- |
| Id | INTEGER | No (generated) | Autogenerated internal identifier; PRIMARY KEY. |
| AllocationSnapshotId | INTEGER | No | Containing disclosure (Contains); each saved snapshot needs an entry. FK to `AllocationSnapshot.Id`. |
| AllocationCategoryId | INTEGER | No | One category used by this entry (Used by). FK to `AllocationCategory.Id`. |
| WeightFraction | REAL | No | Reported category allocation fraction in [0,1]. |

## Additional integrity rules and enforcement

| Rule | Enforcement |
| --- | --- |
| Existing referenced parent; restricted deletes/key changes | Named SQL foreign keys with per-connection enforcement enabled |
| Required fields, scalar types, domains, valid dates and fractions | STRICT tables, NOT NULL and named CHECK constraints |
| Mandatory business identity and scoped uniqueness | Named UNIQUE constraints; scheme/identifier partial unique indexes |
| Matching snapshot/category dimensions | BEFORE INSERT/UPDATE entry triggers plus BEFORE UPDATE dimension triggers on both parent tables |
| At least one identifier for each ETF | validate_database / validated_transaction before COMMIT |
| At least one entry for each saved snapshot | validate_database / validated_transaction before COMMIT |
| Complete allocation total, with rounding tolerance | Transaction validator; Partial/Unknown are exempt |
| Used category has expected verified-edition or disclosure-local ContextKey | Context helpers plus transaction validator |
| Retained source file exists within the project | Transaction validator when capture_root is supplied |
| Actual real-world company/identifier/source/classification accuracy | Dataset provenance and human evaluation; not established by a database constraint |

The validator checks the proposed final state and rolls back a whole write operation on failure. Parent and child rows can be inserted together in one operation. Direct SQL/raw COMMIT can bypass the application-only rules; this limitation and the required transaction boundary are explicit. A known version in the data is not independently verified just because its token matches.

The ContextKey implementation is a deterministic JSON tuple with `scheme:` or `source:` prefix. Known edition: authority/name/version. Unresolved scheme or edition: captured URL/retrieval time/block locator/dimension. See [schema_integration.md](schema_integration.md) for exact helpers, examples and operation contracts.

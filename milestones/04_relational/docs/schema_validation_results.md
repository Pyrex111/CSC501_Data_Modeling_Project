## Environment and commands

- Python 3.12.14; linked SQLite 3.53.1.
- Required minimums: Python 3.10 and SQLite 3.37.0 (STRICT table support).
- Command: `python -m unittest discover -s tests -v` from the repository root.
- Result: **33 tests passed**, zero failures/errors.

All tests create fresh in-memory databases and use explicitly synthetic fixtures. The retained fixture is `tests/fixtures/synthetic_disclosure.txt`; its example.invalid URL does not claim to be a real fund source. These records are not Mason's demonstration dataset.

## Verified behavior

| Area | Observed result |
| --- | --- |
| Fresh schema and autogenerated Id | Schema executes successfully; omitted Id generates an integer; PRAGMA integrity_check returns ok and foreign_key_check returns no violations |
| Business identification | Duplicate customer reference, provider registration within a registry, portfolio reference within an owner, dated holding and snapshot-category pair are rejected |
| Scoped identity | A portfolio reference can be reused by another customer; a registration number can occur in another registry; names/email are not incorrectly made unique |
| ETF identifiers | Duplicate ISINs with NULL exchange are rejected; tickers require exchange; same ticker may occur on a different exchange |
| Unknown classification | Duplicate known edition is rejected; unknown versions remain NULL and distinct; they cannot establish a shared known-edition context |
| Source/disclosure identity | A duplicate URL/capture-time record and duplicate dated allocation block are rejected; another retrieval time is allowed |
| Scalar integrity | Invalid fractions, nonnumeric weights, missing required values, invalid status/dimension values, malformed country/currency codes, invalid calendar dates and noncanonical timestamps are rejected |
| References | Missing parents and deletion of referenced ETF records are rejected; external FK violations are detected after enforcement is restored |
| Dimension consistency | Cross-dimension entry inserts/updates and later parent dimension changes are rejected |
| Parent participation | New ETF without identifier, empty snapshot and deletion of a snapshot's remaining entries cause transaction rollback |
| Atomic creation | Parent and required child can be created together and committed successfully |
| Totals | Invalid Complete totals roll back; Partial/Unknown totals need not equal 1; the inclusive tolerance boundary and configurable tolerance are exercised |
| Context meaning | Unresolved category cannot be reused across captures; an unresolved linked scheme also requires local context; a known edition context can be reused consistently; changing the scheme edition requires context correction |
| Retained evidence | Missing/out-of-root captures cause rollback when capture_root is provided |
| Transaction setup | Foreign-key enforcement is required; nested transactions are rejected rather than silently committed |

## Additional checks

- Compared the revised Draw.io attributes to the actual SQLite columns for every entity: **twelve relations, 63 columns, thirteen FKs**. Removing the FK columns leaves exactly the fifty conceptual attributes, including each entity's Id. No conceptual attributes were dropped or silently added.
- Confirmed every PK is named Id and declared INTEGER, every table/column follows PascalCase, and all twenty-six original entity-to-relationship edges remain represented through their thirteen mapped relationships.
- Ran the schema-only initializer against a new on-disk database: it created twelve empty tables. Repeating it against the existing file was refused and left the file hash unchanged.
- Compiled and visually inspected the relation/constraint listing: one two-column page, displayed as page 3, with no overfull text boxes. This preview used the supplied sample's acmart class and available fallback fonts. The final team report must be compiled and checked in the current ACM template.

## Limits of these results

SQL constraints/triggers enforce row-local and dimension integrity. Parent minimums, contexts, complete totals and optional file-resolution checks rely on the supplied validated application transaction; raw SQL COMMIT can bypass those application rules. File existence does not verify source content. ISIN/country/currency formats do not verify external registry assignments. Real data and semantics still require evidence and human review.

The tests do not establish that the web application works, the team's dataset is sufficient, the current ACM final report is complete, or the final ZIP is ready. Those checks remain part of integration and submission preparation.

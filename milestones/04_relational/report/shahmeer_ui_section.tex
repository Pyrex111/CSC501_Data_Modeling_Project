\subsection{Interface and validation}
Users search by ticker, dimension and allocation date; inspect classification
and source evidence; create disclosures; batch-edit weights; and delete entries.
Portfolio selection displays a holding date alongside separately dated
disclosures, without unsupported aggregation. The prototype operates on
preloaded funds, sources and categories.

Routes call business helpers and DAL functions separately
(Figure~\ref{fig:architecture}). Helpers reject invalid dates, nonfinite or
out-of-range fractions, duplicate categories and empty disclosures. SQL and
transaction checks apply before commit. Rejected creates/updates retain input
and show plain messages: the recorded total 1.04 is rejected, while a coherent
batch saves at 1.0. Full screenshots document each operation and rejection.
